# AI Visibility Platform MVP 現状まとめ

このドキュメントは、依頼者・非エンジニア・依頼者側AIが、このMVPの現状を素早く・正確に説明できるようにするための1ファイルです。技術的な詳細（実装・テスト・設計判断の経緯）は各docsに譲り、ここでは「何ができて、何をまだ保証していないか」を平易な言葉でまとめています。

開発者向けの詳細は[development_status.md](./development_status.md)（現状サマリー）・[13_common_crawl_mvp_design.md](./13_common_crawl_mvp_design.md)（Common Crawl補完の設計）を参照してください。docs全体の読む順番は[00_index.md](./00_index.md)を参照してください。

**最終更新日: 2026-07-29**

## 1. 現在のMVPでできること

現在のMVPでは、ブランド名や公式サイトURLをもとに、Web上でそのブランドがどのような文脈で扱われているかを分析できます。

主に以下を確認できます。

- ブランドと一緒に出現しやすいキーワード
- ブランドが語られている文脈
- Web上の情報から見たブランド認識の傾向
- 改善すべき情報発信ポイント
- AI Overview / ChatGPT観測との比較枠
- Common Crawl補完による過去クロールデータの補助分析

このMVPは、AIの内部学習データを直接見るものではありません。ただし、AIが参照・学習・回答生成に使う可能性のあるWeb上の情報環境を分析することで、AIにどう認識されやすい状態かを推定することを目的としています。

## 2. Common Crawl補完について

Common Crawl補完機能をMVPに追加しました。

Common Crawlは、Web上のページを大規模にクロールして保存している公開データです。これを利用することで、現在入力されたURLだけでなく、過去にクロールされた公式ドメイン配下のページも補助的に分析対象へ加えられます。

画面上では、成功時に以下のように表示されます（表示名・文言はいずれも依頼者確認前の仮のもの、[15_requester_review_items.md](./15_requester_review_items.md)参照）。

```
分析ソース: Common Crawl補完 3件
Common Crawl補完: 取得済み（3件）
対象ドメイン: cybozu.co.jp / クロールIndex: CC-MAIN-2026-25
取得ページ: 1件（取得データ3件から重複除外）
```

「取得データ3件」と「取得ページ1件」が異なるのは、同じURLの複数クロールデータが取得される場合があるためです。その場合、画面では重複URLをまとめて表示し、「取得データN件から重複除外」という説明を添えます。

## 3. Common Crawl補完の位置づけ

Common Crawl補完は、AIの学習内容そのものを保証するものではありません。

位置づけとしては、Web上の情報環境を推定するための補助データです。

つまり、「このページがCommon Crawlに存在する＝AIが必ず学習している」ではありません。

ただし、Common Crawlに存在する情報は、AIモデルの学習データや検索・要約系AIの情報源候補として扱われる可能性があるため、AI Visibility分析における参考情報として価値があります。

## 4. Common Crawl APIの安定性について

検証の結果、Common Crawl Index APIは同じクエリでも成功する場合と失敗する場合があることが分かりました。

確認された挙動は以下です。

- 成功するとJSONが返る
- 504になることがある
- Render環境ではReadTimeoutになることがある
- 何度か試すと成功することがある

そのため、MVPでは以下の方針にしています。

- **Common Crawlが取得できた場合**: 分析データに加える
- **Common Crawlが取得できなかった場合**: 通常分析はそのまま実行する

つまり、Common Crawlは補助機能であり、取得できない場合でもアプリ全体は止まりません。

## 5. fail-fast設計について

外部APIの応答を長時間待つと、ユーザー画面が固まったように見えてしまいます。

そのため、Common Crawl Index APIにはfail-fast budget（デフォルト8秒）を設定しました。

現在は、Common Crawl検索が一定時間内に完了しない場合、補完取得を中断し、通常分析結果を返します。

- **Common Crawlがすぐ取得できる**: 補完データとして分析に追加
- **Common Crawlが不安定・タイムアウト**: Common Crawlなしで通常分析を返す

画面上では未取得時に、以下のような表示になります。

```
Common Crawl補完: 補完データ未取得
理由: Common Crawl補完の取得処理が完了しませんでした
通常分析は継続されています
```

この設計により、外部APIの不安定さがアプリ全体の停止につながらないようにしています。

## 6. 現在の実装状況

現在、以下は実装済みです。

- ブランド名入力
- URL入力
- Webページ取得
- Document化
- 共起語ランキング
- 文脈分析
- ブランド概要スコア
- 改善提案
- AI Overview比較枠
- ChatGPT観測枠
- Common Crawl補完
- Common Crawl取得ページ表示
- Common Crawl未取得時の継続表示
- Common Crawl fail-fast処理
- Vercel / Render上での動作確認

Common Crawlについては、成功時に3件取得し、分析に混ざることを確認済みです。

## 7. 現在のMVPで説明できる価値

このMVPで説明できる価値は、次のようになります。

AIがブランドをどう認識しているかを直接断定するのではなく、AIに認識されやすいWeb上の情報環境を可視化する。

特に、以下のような用途に向いています。

- ブランドがどのようなキーワードと結びついているかを確認する
- 自社サイト上の情報がAIに伝わりやすい構造になっているかを見る
- 競合や市場文脈と比較する前段階の分析を行う
- AI OverviewやChatGPT観測とWeb上の情報環境を比較する
- 改善すべき発信テーマを洗い出す

## 8. 現時点でまだできないこと

MVP段階では、以下はまだ限定的です。

- AIの内部学習データを直接確認すること
- Common Crawlに存在するページがAIに必ず使われたと断定すること
- 複数ブランドの本格比較
- 時系列変化の継続分析
- DB保存
- 定期クロール
- 非同期ジョブ化
- ダッシュボードとしての履歴管理

これらは今後の拡張対象です。

## 9. 今後の拡張候補

次のフェーズでは、以下を検討できます。

- 分析結果のDB保存
- Common Crawl補完の非同期ジョブ化
- 定期クロール
- 時系列比較
- 競合比較
- AI Overview実測の強化
- ChatGPT / Claude / Geminiなど複数AI観測
- 改善提案の精度向上
- 管理画面・レポート出力

特にCommon Crawlは外部APIが不安定なため、今後本格運用する場合は、同期実行ではなく、非同期で取得し、DBに保存し、分析時は保存済みデータを使う構成にするのが安全です（詳細は[02_roadmap.md](./02_roadmap.md)のNext/Later欄、[13_common_crawl_mvp_design.md](./13_common_crawl_mvp_design.md)「0. 現行設計まとめ」参照）。

## 10. 依頼者向けの簡潔な説明

現在のMVPでは、ブランド名や公式サイトURLをもとに、Web上でブランドがどのような文脈・キーワードと結びついているかを分析できます。

また、Common Crawlの過去クロールデータを補助的に取得し、現在のWebページだけでなく、過去に収集された公式ドメイン配下の情報も分析対象に加えられるようになりました。

Common Crawlは外部APIのため取得が不安定な場合がありますが、取得できた場合は分析に加え、取得できない場合も通常分析は継続する設計にしています。

このMVPは、AIの内部学習内容を直接見るものではありませんが、AIに認識されやすいWeb上の情報環境を可視化し、改善すべき情報発信ポイントを見つけるための基盤として機能します。
